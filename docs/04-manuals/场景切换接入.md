# StartMenu 与 GameScene 场景切换

## 实际流程

`StartMenu → 任意键 → 开始游戏 → GameScene（河谷地图、飞机、飞行控制、相机跟随）→ 返回主菜单 → StartMenu`

两个独立场景：

| 场景 | 路径 | 内容 |
|---|---|---|
| StartMenu | `Assets/_Project/Scenes/StartMenu/StartMenu.unity` | 原开始界面、过渡、设置、操作说明、制作名单 |
| GameScene | `Assets/_Project/Scenes/GameScene/GameScene.unity` | 原飞机与飞行逻辑、相机跟随、河谷地图；右上角新增返回入口 |

场景及其 `.meta` 一同移动，保留原 GUID。没有复制飞机、改动飞行模型或把两个场景叠放在一起。

## C# 脚本与按钮绑定

带中文注释的实际脚本位于：

`Assets/_Project/Scripts/UI/Navigation/SceneNavigation.cs`

它使用 `SceneManager.LoadSceneAsync(sceneName, LoadSceneMode.Single)` 切换，先检查目标场景是否已加入并启用，避免缺少 Build Settings 配置时静默失败。Single 会卸载上一场景，避免旧飞机、相机与菜单残留；返回主菜单时恢复 `Time.timeScale`，方便以后接入暂停菜单。

现有“开始游戏”按钮仍绑定 `MainMenuController.StartBattle()`，保留原菜单的防重复点击与淡黑动画；动画结束后调用 `SceneNavigation.LoadGameSceneAsync()`。保留方法名是为了兼容原菜单，实际加载的场景名已更新为 GameScene。

以后新增按钮时，可按以下方式复用：

1. 给按钮或其他当前场景物体添加 `SceneNavigation` 组件。
2. 在 Button 的 **On Click()** 中拖入该组件所在物体。
3. 开始按钮选 **SceneNavigation → StartGame()**；返回按钮选 **SceneNavigation → ReturnToMainMenu()**。

GameScene 已自动创建一个仅属于该场景的右上角“返回主菜单”按钮，绑定 `ReturnToMainMenu()`。不需要再添加第二个返回按钮，也不使用跨场景单例。以后添加暂停菜单可以复用同一方法。

## 编辑器运行入口

`Editor/GameEntrySetup.cs` 将交互式编辑器的 Play 入口设为 StartMenu，因此在 Untitled 或地图场景下点击播放也会先显示开始界面。需要查看入口场景时，使用 **Tools → Dogfight Threat AI → 打开完整游戏入口**。

自动化测试与批处理不覆盖入口，避免影响 Test Runner 或场景专用验证。

## Build Settings 必须配置

打开 **File → Build Settings**，确认 **Scenes In Build** 包含且勾选：

1. `StartMenu`，索引 0（独立游戏启动入口）。
2. `GameScene`，索引 1。

当前工程已写入这两项。以后重新创建工程、复制场景或重命名时仍需检查：**没有加入或没有勾选的场景无法通过 SceneManager 正常加载，运行/打包后的场景切换会报错。**

## 验证

`MenuToBattleTests` 使用真实按钮事件验证：初始提示等待输入、开始进入 GameScene、河谷地图和飞机存在、飞行模型继续运行、返回 StartMenu、再次开始只生成一架出生点处的新飞机。原有菜单测试继续检查设置、面板与按键门控。

2026-10-25 在本机团结引擎验证：18 项 EditMode、5 项 PlayMode 共 23 项全部通过；主工程的编辑器窗口也实际完成 StartMenu 到 GameScene 的切换，显示地图、飞机和返回按钮。
