# 项目分工

版本：v0.1  
日期：2026-10-20  
适用阶段：2026-10 至 2027-05

本文件只定义岗位职责，不指定人员。具体人员由项目负责人安排。一个人可以兼任多个岗位，但同一模块只能有一个负责人。

## 一、岗位设置

| 岗位 | 名称 | 主要方向 |
|---|---|---|
| A | 架构与模拟 | Core、战斗规则、集成、评审 |
| B | AI 算法 | 威胁网格、行为决策、寻路、批量对战统计 |
| C | 网络传输与网关 | 客户端连接、网关、传输、消息序列化 |
| D | 逻辑服务器与房间状态 | 服务器权威、房间生命周期、快照广播 |
| E | UI 与内容 | HUD、菜单、雷达、场景与内容装配 |

岗位与立项书三条主线的对应关系：

| 主线 | 主要负责岗位 |
|---|---|
| 2D 空战场景与交互 | A、E |
| 实时威胁评估与动态决策 AI | B |
| 网络联机 | C、D |

## 二、岗位职责

### 岗位 A：架构与模拟

负责范围：

- `Scripts/Core/Flight`：飞行模型与状态
- `Scripts/Core/Battle`：BattleSimulation 与固定步推进
- `Scripts/Core/Arena`：边界规则
- `Scripts/Core/Collision`：命中判定与伤害结算
- `Scripts/Core/Combat`：机炮、导弹与武器事件
- `Scripts/Gameplay/Flight`：PlayerController 等胶水
- `Scripts/Gameplay/Config`：配置类与转换
- `Scripts/Gameplay/View/PlayerView.cs`、`CameraFollow.cs`
- `Scripts/Gameplay/World`：调试视图与背景参照
- `Settings/Rules`：边界、威胁网格等规则配置
- `docs/02-design/架构约定.md`

职责：

1. 维护 Core 的编译边界，保证 Core 不引用 UnityEngine。
2. 定义并维护共享契约：`IFlightInputSource`、`IWorldView`、`BattleEvent`、`BattleSetupSpec`。
3. 实现飞行、碰撞、伤害、得分、胜负等核心规则。
4. 负责客户端与逻辑服务器的模拟一致性。
5. 负责代码评审、测试标准和版本合并。
6. 实现机炮命中扫描、直线导弹与第二阶段追踪导弹。

第一、二周交付：

- 完成 Phase 1 的提交与回归测试。
- 给出 `BattleSimulation`、`BattleEvent`、`IWorldView` 的初版定义。
- 给出状态快照字段清单，供 UI 与网络使用。
- 与岗位 B 确认 AI 只通过 `FlightInput` 影响模拟。
- 与岗位 C、D 确认协议中“输入、快照、事件”的边界。
- 给出 `WeaponSpec`、武器事件类型（`GunFired`、`MissileLaunched`、`Hit`、`Destroyed`）与机炮/导弹的初版规则。

验收标准：

- Core 在无 Unity 环境下可编译。
- EditMode 测试全部通过。
- 新增规则有对应测试。
- 共享契约变更均有文档记录。

### 岗位 B：AI 算法

负责范围：

- `Scripts/Core/AI`：行为树、决策、目标选择
- `Scripts/Core/Threat`：威胁网格
- `Scripts/Core/Pathfinding`：BFS、A*
- `Settings/AI`：AiProfile 配置
- `Tests/EditMode` 中与 AI、威胁、寻路相关的测试

职责：

1. 实现威胁评估模型，按队伍维护威胁网格。
2. 实现巡逻、搜索、追击、攻击、规避等行为及其切换。
3. 实现目标搜索、追击路径与规避路径规划。
4. 实现三档 AI 难度，并保证难度差异来自决策质量，而不是血量、伤害或速度加成。
5. 提供批量对战与胜率统计工具，用于验证难度分级。
6. 若实现追踪导弹，实现导弹规避行为，并在威胁网格中计入导弹威胁。

约束：

- 只写纯 C#，不得引用 UnityEngine。
- AI 只能输出 `FlightInput`，不得直接修改飞机状态。
- 通过 `IWorldView` 读取世界，不直接依赖 `BattleSimulation` 内部字段。
- 单次决策应有性能预算，必要时错峰执行。

第一、二周交付：

- 阅读架构约定与 Player 移动说明。
- 实现“直冲玩家”的 AI 原型，使用假世界数据在 EditMode 中跑通。
- 提交 3 条以上测试：输入合法性、目标选择、同输入同结果。
- 给出威胁网格的字段与更新频率草案。

验收标准：

- AI 原型不依赖 Unity，可在测试中独立运行。
- AI 不修改状态，只输出输入。
- 同种子、同输入下结果可复现。

### 岗位 C：网络传输与网关

负责范围：

- `Scripts/Network/Client`：客户端连接、重连、消息收发
- `src/server/GatewayServer`：连接认证、消息路由
- `src/shared/Protocol`：共享协议（与岗位 D 共同负责）
- 传输层选型与接入：TCP、KCP、Mirror
- 网络日志与调试工具

职责：

1. 实现客户端与网关之间的连接、认证、断线重连。
2. 实现网关的消息接收、解析与转发。
3. 维护协议消息的序列化与版本字段。
4. 提供联调工具，能查看收发的消息内容。
5. 与岗位 D 共同维护共享协议，字段变更需双方确认。
6. 传输开火、导弹发射、命中与击毁事件。

第一、二周交付：

- 协议消息清单：登录、房间、输入、快照、事件。
- 一个最小的客户端与网关收发 demo。
- 明确哪些消息经网关转发，哪些由逻辑服处理。
- 断线重连的流程草案。

验收标准：

- 客户端断开后能重连，不产生重复会话。
- 协议消息可读、可版本化。
- 网关不承担战斗规则计算。

### 岗位 D：逻辑服务器与房间状态

负责范围：

- `src/server/LogicServer`：房间生命周期、战斗循环、服务器权威
- `src/shared/Protocol`：共享协议（与岗位 C 共同负责）
- 服务器端测试与压测脚本

职责：

1. 实现房间创建、加入、开始、结算、销毁。
2. 在服务器端运行 `BattleSimulation`，统一处理输入、碰撞、伤害与胜负。
3. 生成状态快照与事件，按固定频率广播。
4. 实现断线重连、观战与房间状态恢复。
5. 保证服务器不依赖 Unity 场景与 MonoBehaviour。
6. 在服务器端执行武器判定，并维护冷却、弹药与锁定状态。

第一、二周交付：

- LogicServer 工程骨架。
- 一个不接 Unity 的固定步循环 demo，可使用假输入。
- 房间状态机草案：等待、加载、战斗、结算。
- 快照与事件的广播格式草案。

验收标准：

- 服务器能独立运行，不加载 Unity 场景。
- 同一房间内的战斗结果由服务器决定。
- 客户端无法通过本地修改影响服务器判定。

### 岗位 E：UI 与内容

负责范围：

- `Scripts/UI/HUD`：血条、速度、得分、越界警告
- `Scripts/UI/Menu`：主菜单、设置、难度选择
- `Scripts/UI/Radar`：雷达与小地图
- `Prefabs/UI`、`Prefabs/Aircraft`、`Prefabs/Weapons`、`Prefabs/FX`
- `Scenes` 中的 UI 布局与内容装配
- `Settings/Aircraft`、`Settings/Weapons` 等内容资产
- `Art`、`Audio` 的接入与整理

职责：

1. 实现 HUD、菜单、设置、雷达、结算等界面。
2. 负责场景、prefab 与内容资产的装配。
3. 负责地图布局、敌机配置、特效与音效接入。
4. 实现难度选择界面，读取 `AiProfile` 与玩家覆盖配置。
5. 维护 UI 与内容相关的文档和资产清单。
6. 实现武器与锁定 UI、导弹尾迹、爆炸与命中反馈。

约束：

- UI 只读取状态快照与事件，不修改血量、位置、伤害或胜负。
- 规则问题交由岗位 A 处理，不得在 UI 内复制一套判定。
- 场景和 prefab 修改前应先同步，避免多人同时编辑。
- 内容扩展优先通过 asset 完成，不为单个内容编写专用代码。

第一、二周交付：

- 用假数据完成一版 HUD 与主菜单。
- 搭好 Battle 场景的 UI 层级。
- 输出内容资产清单：飞机、武器、特效、音效。
- 新增一架 AircraftData asset，在不改代码的情况下接入并验证。
- 列出武器、导弹尾迹、爆炸与锁定 UI 的资产清单。

验收标准：

- UI 不依赖模拟内部字段，只依赖约定的状态与事件。
- 新增内容资产不需要修改代码。
- 场景与 prefab 保存完整，无 Missing 引用。

## 三、共享契约

以下内容属于跨岗位契约，变更前需要相关岗位确认，并在 `docs/02-design/` 留记录。

| 契约 | 内容 | 提供方 | 使用方 |
|---|---|---|---|
| `IFlightInputSource` | 输入源接口 | A | B、C、D、E |
| `IWorldView` | AI 只读世界视图 | A | B |
| `BattleEvent` | 开火、命中、击毁、得分等事件 | A | C、D、E |
| `BattleSetupSpec` | 对局参与者与初始配置 | A | C、D、E |
| `AircraftSpec` | 飞机纯配置 | A | B、C、D |
| `WeaponSpec` | 武器纯配置 | A | B、C、D、E |
| 协议消息 | 登录、房间、输入、快照、事件 | C、D | A、B、E |
| 稳定 ID | 配置与实体的身份标识 | A | 全部岗位 |

变更规则：

1. 新增字段或修改语义前，在团队内说明用途。
2. 协议字段变更需岗位 C 与岗位 D 双方确认。
3. Core 契约变更由岗位 A 确认，并补充测试。
4. 变更完成后更新设计文档，不只留在聊天记录里。

## 四、协作规则

1. 一个文件、一个场景、一个 prefab 同时只有一个负责人。
2. 多人需要改同一场景时，先约定顺序，改完立即保存并同步。
3. 切换或合并分支前关闭 Unity，避免场景与 meta 文件冲突。
4. 新增或删除资源时，`.cs` 与 `.meta`、场景与 prefab 必须一起提交。
5. 每人提交前运行 EditMode 测试，至少保证自己负责的模块有测试。
6. 共享契约与跨岗位接口由岗位 A 评审。
7. 每周安排一次 15 分钟的接口同步，内容包括：AI 需要哪些世界数据、UI 需要哪些状态、网络需要哪些消息。

## 五、交付节奏

| 时间 | 目标 |
|---|---|
| 2026-10 | 完成 Core 分层；BattleSimulation 初版；机炮与直线导弹；AI 原型；协议骨架；UI 假数据版本 |
| 2026-11 | 威胁网格与热力图；AI 第一版；追踪导弹（视进度）；前后端联调；房间管理基础 |
| 2026-12 至 2027-02 | 三种对战模式；回放；观战与聊天；三档 AI 交叉对比实验 |

追踪导弹属于第二阶段内容。若进度不足，应在结题文档中说明与立项书的差异。

## 六、能力匹配建议

| 岗位 | 建议背景 |
|---|---|
| A | 软件工程，熟悉 C# 与 Unity，能承担架构与评审 |
| B | 数学、统计或算法方向，愿意写纯 C#，不依赖 Unity |
| C | 物联网、通信或网络方向，了解 Socket 与消息收发 |
| D | 软件工程，偏向服务端与并发，了解 TCP/UDP 与状态同步 |
| E | 软件工程或数字媒体，熟悉 Unity UI、prefab 与场景编辑 |

背景只作为安排参考。岗位 B 如果 C# 不熟，先写控制台原型，再进入 Unity 工程；岗位 C、D 如果对网络协议不熟，先完成最小收发 demo，再扩展房间与同步。

## 七、冲突处理

1. 规则归属不清时，由岗位 A 决定放在 Core 还是表现层。
2. UI 需要新数据时，向岗位 A 提出字段需求，不直接读取模拟内部字段。
3. AI 需要新世界信息时，向岗位 A 提出 `IWorldView` 扩展，不直接访问 `BattleSimulation`。
4. 协议字段冲突时，由岗位 C 与岗位 D 协商，岗位 A 评审对模拟的影响。
5. 场景或 prefab 冲突时，先保存各自修改，再约定合并顺序；不得直接使用“Discard All Changes”。
